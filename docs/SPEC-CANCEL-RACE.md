# SPEC：后台上游推送与「取消」的一致性（S-B5）

- 作者：architect ｜ 日期：2026-10-02 ｜ 状态：已开卡（D2 收尾时由 coder 上报，architect 受理）
- 关联：`docs/SPEC-LOCAL-FIRST-SUBSCRIBE.md`（S-B2 本地优先）、`docs/ARCHITECTURE-REVIEW-2026-10-01.md`
- 归属链：本 spec 是 S-B2 的**收尾条款**——S-B2 把上游推送挪到请求返回之后，就必须补上「推送前重查本地行」这一步，否则取消会漏到上游

## 0. 问题（实证，2026-10-02 00:10）

生产日志（`backend/logs/unisub.log`，同一台机、同一次冒烟）：

| 时刻 | 事件 |
|---|---|
| 00:10:17.665 | `订阅了 盗梦空间 (movie)`（tmdb_id=27205） |
| 00:10:17.772 | `取消订阅 盗梦空间`（**+107ms**） |
| 00:10:17 | `NextFind 订阅成功: 盗梦空间 (movie, tmdb_id=27205)`（后台任务在飞） |
| 00:10:32.740 | `MP 镜像 — 创建订阅: 盗梦空间 电影 (mp_sub_id=2263)`（**取消后 +15s**） |

`activity_logs` 三条时间戳吻合；库内 `subscriptions`/`mp_subscription` 均 **0 行**（父行删除已连带）。
→ **MP 侧留下了 unisub 无记录、无本地镜像的「僵尸订阅」（mp_sub_id=2263）**。NF 侧同理，只是这次时序恰好赶在取消前完成。

根因：`schedule_upstream` 的任务在请求返回后独立跑，**不感知该行是否已被取消/删除**。

## 1. 组件边界

- 「取消」是**本地事实**（行不在了）；后台推送任务必须在**每个上游调用之前重查本地行是否存在**。
- 行不存在 → 放弃该步并写**可见**日志（不静默），不得再调 NF/MP 建订阅。
- 判定状态一律读库，**不许用内存标记**（进程重启即丢，且多 worker 不共享）。

## 2. 接口契约

- `schedule_upstream(...)` 产生的后台任务：每步（NF 建订阅 / MP 镜像之前）执行
  `select(Subscription).where(Subscription.id == sub_id)`；返回 `None` → `return`（放弃后续上游动作）。
- 跳过时落一条可见记录：`activity_logs` `action="system"`，message 含「订阅已取消，跳过上游推送」+ 标题。
- 触发频率不变（仍是 commit 之后的独立会话任务）；失败/跳过都不回滚本地、不影响请求返回值。

## 3. 数据格式

- **不变**：不加表、不加列、不加墓碑字段。存在性检查用主键查询即可覆盖本期场景。

## 4. 量级约束

- 每后台任务增加 1~2 次本地查询（<1ms），**不增加出网调用**。
- 订阅请求路径 p95 仍 **< 500ms**（本改动不碰请求路径）。

## 5. 非目标（本卡明确不做）

- **不做**「取消时主动撤销上游已建的订阅」（那是 `unsubscribe` 的语义，本期仍同步等 NF，且要处理 MP 侧删除 → 单独卡）。
- 不引入墓碑表 / 状态机 / 消息队列；不做推送去重、不做顺序保证。
- 不改 NF/MP 客户端、不改 http_client、不改 `orchestrator.subscribe` 的返回契约。

## 6. 验收

1. **回归测试（桩，必须真 RED 过）**：订阅 → 立即 DELETE → 手动触发后台任务 →
   断言 NF/MP 的「建订阅」桩调用次数 **= 0**，且活动日志出现「跳过上游推送」。
   没有这条测试不算完成。
2. **真机复验**：订阅一部 → 100ms 内取消 → 30s 后 MP 订阅日志**不得**出现该条目的「创建订阅」（或经 MP API 列表确认不存在）。
3. `cd backend && unset UNISUB_DATABASE_URL && .venv/bin/python -m pytest -q` 全绿（基线 205）。
4. `sudo supervisorctl restart unisub:unisub_backend` → `sleep 3` → `/health` = healthy。
5. **顺带清理**：删掉本次遗留的 MP 僵尸订阅 `mp_sub_id=2263`（用项目已有 MP 客户端；不许打印 token / 不落明文）。

## 7. 红线

- 只查错不重写：不改动 S-B2/S-B3 已定契约（本地先落库 + commit 后返回 + 幂等）。
- 不许用「取消时删 MP」之类的越权动作掩盖问题；僵尸清理仅限上面那一条 id。
- 不许伪造通过：桩调用计数必须是测试真实断言出来的。
