## 1. 结论展开

### 1.1 为什么「JEV 当主决策器」不行

把 712 条真实历史条目的**完整候选池**（重建后 1~40 个候选）交给 JEV，让它同时回答「有没有同一部作品」和「是哪一个」：

- 它的 `which` 选对真值候选的比例只有 **93.6%（629/672）**——这是召回的天花板；
- 再叠加「`same_work ≥ 阈值` 且 `which ≠ none`」的双条件，召回进一步掉到 91.4%（τ=0.5）→ 76.6%（τ=0.7）；
- 误订确实降了（2.81% → 0.84%~1.54%），但召回损失远超 5pp 门禁。

关键失效子群：**源年份缺失 + 池内多个同名候选**（36 条）。这类样本 A 侧 100% 正确（它按投票数取同名候选），而 JEV 主决策器召回只有 **8.3%（τ=0.7）/ 19.4%（τ=0.5）**：候选池里两三个同名的候选都没有年份可分辨，JEV 给出 0.42~0.45 的中间概率。它不是判错，是**在信息不足时拒答**——而主决策器形态下「拒答」就等于漏订。

> 这与探针（`scripts/jev_ab_probe.py`）的用法差异是本质的：探针每次只给 JEV **一个**候选，主决策器形态要求它在 20~40 个候选里挑，两者不是同一个任务。

### 1.2 为什么「JEV 当采纳闸门」可以

A 侧的 20 个误订**全部**落在同一个根因上：候选池里没有任何同名候选时，`matching.py` 的 `_best_by_vote` 兜底把「投票数最高」的候选当成结果（`title_similar_enough` 判不过却仍被返回，见 `pipeline/matching.py:64` 附近）。这正是应该被 JEV 拦下的模式。

把「A 选中的那一个候选」单独交给 JEV 判定（**探针同形态**）：

- JEV 拦下 37 次采纳，其中 **12 次正是那批模糊候选**（概率 0.05~0.49），误订从 20 降到 8；
- 但同时误杀 25 条真匹配——**全部是同名、只是年份口径不同**（源年份 vs TMDB 上映年），因为指令里写了「同名但年份不同视为不同作品」。

把年份从指令里降级（弱年份指令，见 §7）后（A+V2，仍带 `which` 条件）：误订降到 2，召回回到 95.98%。
最后去掉闸门形态里没有意义的 `which` 条件（A+V2s）：**误订 2 条，召回 99.11%**。

## 3. 标签口径（重要，决定了所有数字的含义）

**主口径 L2**：候选 `id ∈ truth_ids` ⟺ 候选标题归一化后与源标题**完全相等**。不比对年份。
**敏感口径 L1**（年份严格）：在上式基础上再要求年份差 ≤1（仅 189 条有年份的样本可算）。

为什么不照抄卡片里「历史 `tmdb_id` 在候选里 → 正标签」：该口径**循环**——历史后端只会在候选池里挑，历史 id 天然出现在池里，正样本会变成 100%，没有负样本，无法度量误订。因此改用与历史决策**无关**的客观标题判据，同时把「与历史决策一致率」作为独立的复现保真度指标报告：

- A 侧复刻与历史后端决策一致率 **668/712 = 93.8%**（44 例不一致：A 拒绝/历史无 id 19、A 采纳/历史无 id 11、A 拒绝/历史有 id 2、A 采纳/历史有 id 12）。
- 原因：候选池是**今天**重建的，NF/TMDB 侧数据与订阅当日不同（条目增删、年份水合差异），且 682 条历史判定里有 473 条的历史 `tmdb_id` 根本不在今天的池子里。这是回放法的固有偏差，不是 A 侧实现的缺陷——A 侧代码路径与生产一致（同一 `matching.py`）。

**标签噪声（务必一并读）**：40 条「池内无同名作品」的样本里，A 侧采纳的 20 条并非都是真误订。至少 8 条的差异只是**标点/副标题写法**（「银魂 吉原大炎上」vs「银魂：吉原大炎上」、「你们先走我断后」vs「『你们先走我断后』」、「年会不能停！2」vs「年会不能停！2」），JEV 对它们给 0.66~0.86（判为同一部作品），比我的标签更可能是对的。也就是说 **A 侧的真实误订率被口径高估了**，A+V2s 残留的 2 条误订（两条都是「银魂：吉原大炎上」）大概率也是标签问题而非真误订。

判定规则（全部在脚本里，不在提示词里）：
- `B`：`same_work__0.noul ≥ τ` **且** `which__0.choice ∈ {cand_1..cand_n}`

## 7. 对 `SPEC-JEV-DECISION.md` 的修订建议

1. **接入形态**：规范里「JEV 承担同一作品判定」应明确为**采纳闸门**，而不是「用 JEV 在候选池里选片」。候选选择继续由 `matching.py` 负责；JEV 只回答一个二元问题。
2. **年份不要交给 JEV 做数值判定**（探针 C4 已提示）。实测：年份严格指令让闸门误杀 25 条真匹配（源年份 vs TMDB 上映年口径）。年份比较留在代码里（`search.py`/`matching.py` 已有），JEV 指令改为「标题完全一致且类型一致即为同一部作品，年借口径差异不算不同；标题不完全一致、副标题/版本/季数/类型不同才算不同」。
3. **闸门请求只给一个候选**，且**不解析 `which`**（21 例自相矛盾）。
4. **阈值 τ=0.5**（区间 [0.5, 0.9] 等价），避免采用探针里的 0.97 —— 那是「单候选、强指令」档，与本场景样本分布不同。
5. 规范里若沿用「历史 tmdb_id 作正标签」，需补一句：该口径只能用于**保真度**核对，不能用于度量误订率（循环）。

## 8. 给 Phase 4B 的落地建议

- **形态**：`A 采纳 → JEV 闸门 → 放行/降级`。闸门请求 state 只放 A 选中的那一个候选，问题只问 `same_work`。
- **fail-closed + 降级可见**（卡片既定要求）：JEV 超时/异常/字段缺失 → **不放行**（按拒绝处理），并写 `activity_logs` 一条 `system` 级「JEV 闸门不可用，已按下单保守处理」记录；连续失败 N 次自动熔断回 A 侧原行为（避免整批漏订），熔断事件必须进日志与告警。
- **影子模式先行**：先只记录「闸门本会拒绝」的判定，不真正影响下单；跑满一周对比人工复核，再切生效。
- **从宽处理零信号样本**：源年份缺失 + 候选无评分/无简介时，JEV 的否定置信度不可靠（§5.3 的 5 条误杀）。建议此类样本要求 `same_work ≥ 0.8` 才拦，其余走 A 侧原逻辑。
- **成本**：只有 A 采纳的条目才会触发闸门（本次 702/712 ≈ 98.6% 的条目 A 采纳，实际触发率取决于上游），单次 $5.1e-05，日常量级可忽略。

## 10. 局限

1. **回放保真度 93.8%**：候选池是今日重建，非订阅当日快照。所有绝对误订率都有此偏差，但 A 与 B 在同一池上对比，**相对结论稳定**。
2. **标签口径含噪**：40 条负样本里约 8 条是标点/副标题差异，即 A 的真实误订率低于 2.81%、A+V2s 的 2 条残留也大概率非真误订。宁可把它当作「口径噪声上界」，不要当精确值。
3. **样本偏置**：全部来自 `auto_subscribe_history.json` 的 handled 条目，且以 tv 为主（344/712）；不含上游被更早阶段过滤掉的条目（那些根本没走到匹配）。
4. **未做真实写入验证**：本阶段只读，未在生产链路验证；影子模式是 4B 的事。
5. **单模型单版本**：`jev-1.13.0`，单一 515/524 批次各跑一次，未做多次重复以估计方差；τ∈[0.5,0.9] 的平台期是对抖动的部分补偿，但正式切换前建议重复一轮（成本 < $0.05）。
